# 机器人管理实现方案

日期：2026-07-07

## 1. 背景

当前 AI 客服后台里的“店铺机器人配置”还是占位内容。随着知识库管理、图片素材库、Prompt 注入、自动回复和聚合界面手动生成回复逐步接通，继续把“模型选择”“知识库绑定”“平台配置”分散在不同入口，会让后续链路越来越难判断：

- 当前平台到底使用哪个模型。
- 当前平台是否应该走知识库检索。
- 当前平台绑定了哪些知识库。
- 自动回复和手动生成回复是否使用同一套配置。
- 机器人停用、知识库删除、模型配置变更后如何降级。

因此需要把客服回复策略收束成一个独立实体：机器人。

机器人不是一个新的大模型服务，而是一套可配置的 AI 客服策略。它负责声明“用哪个模型、查哪些知识库、适用于哪些店铺、是否启用”。聚合界面平台按钮只绑定机器人，不再直接绑定知识库。

## 2. 设计目标

首版机器人管理主要解决配置归一问题：

1. 支持在 AI 客服后台创建、编辑、删除、启停机器人。
2. 一个机器人可以绑定一个模型配置。
3. 一个机器人可以绑定一个或多个知识库。
4. 一个机器人可以填写适用店铺，用于展示、筛选和人工识别。
5. 聚合界面左侧平台按钮支持右键绑定一个机器人。
6. 平台按钮同一时间最多绑定一个机器人。
7. 手动“生成本条回复”和“AI 自动回复”复用同一套机器人配置解析逻辑。
8. 未绑定机器人时，使用聚合输入框当前选择的模型，不走知识库检索。
9. 机器人停用、模型不可用、知识库为空等异常情况需要有明确降级和日志。

## 3. 非目标

首版不做以下能力：

- 不做复杂租户权限。
- 不做多机器人同时竞价或路由。
- 不做按商品、按客服账号、按会话类型的细粒度绑定。
- 不做机器人版本发布、回滚和灰度。
- 不做 Prompt 在线模板编辑器。
- 不做复杂策略引擎。
- 不把最终回复生成迁移到知识库服务端。

这些能力等真实需求稳定后再扩展。

## 4. 核心概念

### 4.1 机器人

机器人是一套客服回复策略，建议字段如下：

| 字段 | 说明 |
| --- | --- |
| robot_id | 内部生成 ID，例如 `rob_xxx`，用户不可编辑 |
| robot_name | 机器人名称，用户可编辑 |
| model_config_id | 绑定的模型配置 ID，例如 DeepSeek、豆包等已有配置 |
| knowledge_base_ids | 绑定的知识库 ID 列表，可为空 |
| shop_names | 适用店铺，用户填写，可存为文本或列表 |
| enabled | 是否启用 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

机器人名称用于用户识别，例如：

- 拼多多键盘售前机器人
- 拼多多售后机器人
- 官方旗舰店通用客服机器人
- 常见问答机器人

### 4.2 平台绑定机器人

聚合界面左侧平台按钮只绑定机器人，不直接绑定知识库。

示例：

```text
PDD Web 平台按钮
  -> 绑定 robot_id = rob_pdd_keyboard_presale
  -> 机器人内声明模型、知识库和启用状态
```

这样平台侧只关心“我当前用哪套机器人策略”，不需要同时维护模型、知识库、素材库等多份绑定关系。

### 4.3 适用店铺

机器人里的“适用店铺”首版只作为描述、展示和筛选字段，不作为强制生效条件。

真正生效关系以“平台按钮绑定机器人”为准。这样可以避免歧义：

```text
机器人写了适用店铺，但平台未绑定
  -> 不生效

平台绑定了机器人，但适用店铺文字没有完全匹配当前店铺名
  -> 首版仍按绑定关系生效
```

后续如果需要自动匹配店铺，再单独设计店铺实体和绑定关系。

## 5. 运行规则

### 5.1 手动生成回复

用户在聚合界面点击“生成本条回复”时：

```text
当前平台
  -> 查询是否绑定机器人
  -> 如果绑定且机器人启用
       -> 使用机器人模型配置
       -> 如果机器人绑定知识库，则走知识库检索
       -> 如果机器人未绑定知识库，则跳过知识库检索
  -> 如果未绑定机器人
       -> 使用聚合输入框当前选择的模型
       -> 不走知识库检索
```

### 5.2 自动回复

自动回复也走同一套配置解析逻辑。

建议首版规则：

```text
开启 AI 自动回复
  -> 当前平台必须绑定一个启用状态的机器人
  -> 机器人必须有可用模型配置
  -> 知识库可为空，为空则跳过检索
```

如果当前平台未绑定机器人，建议禁止开启自动回复，并给出明确提示：

```text
当前平台未绑定机器人，请先在平台按钮右键菜单中绑定机器人。
```

这样可以降低误发风险。手动生成回复可以允许未绑定机器人回退到当前模型，但自动回复更适合要求配置明确。

### 5.3 模型选择按钮

聚合界面输入框里的模型选择按钮继续保留，但它只在当前平台未绑定机器人时生效。

规则：

```text
平台已绑定启用机器人
  -> 使用机器人里的模型配置
  -> 输入框模型选择按钮仅作为显示或禁用提示

平台未绑定机器人
  -> 使用输入框模型选择按钮选择的模型
  -> 不走知识库检索
```

UI 上可以在模型选择按钮附近或 tooltip 中提示：

```text
当前平台已绑定机器人，将使用机器人模型配置。
```

### 5.4 知识库检索

只有机器人绑定了知识库时才走知识库检索。

```text
机器人绑定知识库数量 > 0
  -> 使用这些知识库作为检索范围

机器人未绑定知识库
  -> 跳过知识库检索

平台未绑定机器人
  -> 跳过知识库检索
```

这样可以避免“未绑定机器人但误用了默认知识库”的隐性行为。

### 5.5 多模态模型

如果最新客户消息包含图片：

```text
机器人模型支持多模态
  -> 图片随请求传给模型

机器人模型不支持多模态
  -> 不传图
  -> trace 记录 vision_not_supported
  -> Prompt 中只描述存在图片消息，避免假装看到了图片
```

豆包这类支持图片输入的模型适合绑定到需要图片理解的机器人。

## 6. 数据模型建议

首版可以继续沿用本地 SQLite 或现有配置存储方式。建议拆成两类表或配置节点。

### 6.1 robots

```sql
CREATE TABLE robots (
  robot_id TEXT PRIMARY KEY,
  robot_name TEXT NOT NULL,
  model_config_id TEXT NOT NULL,
  shop_names TEXT NOT NULL DEFAULT '',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

`shop_names` 首版可以保存为换行文本或 JSON 数组。若已有 JSON 工具链，建议保存 JSON 数组。

### 6.2 robot_knowledge_bases

```sql
CREATE TABLE robot_knowledge_bases (
  robot_id TEXT NOT NULL,
  knowledge_base_id TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (robot_id, knowledge_base_id)
);
```

### 6.3 platform_robot_bindings

```sql
CREATE TABLE platform_robot_bindings (
  platform_key TEXT PRIMARY KEY,
  robot_id TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

`platform_key` 可以沿用当前聚合侧平台标识，例如：

- `pdd_web`
- `wechat`
- `qianniu`
- `qq`

如果后续同一平台存在多个账号或多个店铺，再升级为：

```text
platform_key + account_id/shop_id
```

## 7. 后台 UI 设计

### 7.1 店铺机器人配置页

页面标题：

```text
店铺机器人配置
```

页面说明：

```text
在这里管理不同店铺或场景使用的 AI 客服机器人。机器人会声明模型、知识库和启用状态，聚合界面平台按钮可绑定其中一个机器人。
```

表格列：

| 列 | 说明 |
| --- | --- |
| 机器人名称 / ID | 名称展示为主，ID 小字展示 |
| 模型配置 | 展示模型配置名称 |
| 知识库 | 展示已绑定知识库，多个时用标签或省略展示 |
| 适用店铺 | 展示用户填写的店铺 |
| 状态 | 启用 / 停用 |
| 操作 | 编辑、复制、停用/启用、删除 |

顶部按钮：

```text
+ 新建机器人
```

### 7.2 新建 / 编辑机器人弹窗

字段：

- 机器人名称：必填。
- 模型配置：下拉单选，来源于现有模型配置。
- 知识库：多选，来源于已创建知识库。
- 适用店铺：文本输入，支持多行。
- 状态：启用开关。

校验：

- 机器人名称不能为空。
- 模型配置不能为空。
- 知识库可以为空。
- 删除机器人前，如果已有平台绑定，需要二次确认。

### 7.3 聚合界面平台按钮右键菜单

在平台按钮右键菜单中增加：

```text
绑定机器人
解绑机器人
当前机器人：xxx
```

绑定机器人可以打开一个轻量选择弹窗：

```text
选择机器人
  - 拼多多键盘售前机器人
  - 拼多多售后机器人
  - 官方旗舰店通用机器人
```

如果机器人被停用或删除：

```text
当前机器人：已失效
```

并在生成回复或自动回复时阻断或降级。

## 8. 接口设计建议

如果机器人配置由 C++ 客户端本地管理，可以先不新增 Python 接口。知识库仍由 Python 服务提供，机器人只是 C++ 侧选择检索范围。

如果希望配置也统一走 Python 服务，可以新增以下接口。

### 8.1 机器人列表

```http
GET /api/robots
```

返回：

```json
{
  "robots": [
    {
      "robot_id": "rob_pdd_keyboard_presale",
      "robot_name": "拼多多键盘售前机器人",
      "model_config_id": "model_doubao",
      "knowledge_base_ids": ["kb_keyboard", "kb_faq"],
      "shop_names": ["官方旗舰店"],
      "enabled": true,
      "created_at": "2026-07-07T10:00:00",
      "updated_at": "2026-07-07T10:00:00"
    }
  ]
}
```

### 8.2 创建机器人

```http
POST /api/robots
```

请求：

```json
{
  "robot_name": "拼多多键盘售前机器人",
  "model_config_id": "model_doubao",
  "knowledge_base_ids": ["kb_keyboard", "kb_faq"],
  "shop_names": ["官方旗舰店"],
  "enabled": true
}
```

### 8.3 更新机器人

```http
PUT /api/robots/{robot_id}
```

### 8.4 删除机器人

```http
DELETE /api/robots/{robot_id}
```

如果机器人已被平台绑定，建议返回明确错误或要求强制删除参数：

```json
{
  "ok": false,
  "error": "robot_in_use",
  "message": "该机器人已被平台绑定，请先解绑后再删除。"
}
```

### 8.5 平台机器人绑定

```http
GET /api/platform_robot_bindings
PUT /api/platform_robot_bindings/{platform_key}
DELETE /api/platform_robot_bindings/{platform_key}
```

绑定请求：

```json
{
  "robot_id": "rob_pdd_keyboard_presale"
}
```

## 9. 生成回复链路

建议把配置解析收敛成一个独立步骤：

```text
resolveAiReplyConfig(platformKey, selectedModelFromInput)
```

返回：

```text
AiReplyRuntimeConfig
  - source: robot | manual_model
  - robot_id
  - robot_name
  - model_config_id
  - knowledge_base_ids
  - vision_supported
  - auto_reply_allowed
```

手动生成和自动回复都调用它。

### 9.1 手动生成链路

```text
点击“生成本条回复”
  -> resolveAiReplyConfig()
  -> 提取最新客户咨询 query
  -> 如果有 knowledge_base_ids，则按这些知识库检索
  -> 构造 Prompt
  -> 调用模型
  -> 写 aggregate_ai_trace 日志
```

### 9.2 自动回复链路

```text
收到新入站消息
  -> 检查当前平台是否开启自动回复
  -> resolveAiReplyConfig()
  -> 如果未绑定启用机器人，则跳过并记录日志
  -> 复用“生成本条回复”逻辑
  -> 发送回复
  -> 写 aggregate_auto_reply 日志
```

## 10. 日志要求

为了后续排查，建议 trace 中补充机器人配置解析结果。

手动生成日志：

```text
[机器人配置]
platform_key: pdd_web
config_source: robot
robot_id: rob_pdd_keyboard_presale
robot_name: 拼多多键盘售前机器人
model_config_id: model_doubao
knowledge_base_ids: kb_keyboard,kb_faq
robot_enabled: true
```

未绑定机器人时：

```text
[机器人配置]
platform_key: pdd_web
config_source: manual_model
selected_model: deepseek
knowledge_search: skipped
skip_reason: platform_not_bound_to_robot
```

自动回复日志：

```text
[自动回复机器人检查]
platform_key: pdd_web
auto_reply_enabled: true
robot_bound: false
result: skipped
reason: platform_not_bound_to_robot
```

异常场景需要明确 reason：

- `platform_not_bound_to_robot`
- `robot_disabled`
- `robot_deleted`
- `model_config_missing`
- `knowledge_base_missing`
- `vision_not_supported`

## 11. 降级策略

| 场景 | 手动生成回复 | 自动回复 |
| --- | --- | --- |
| 平台未绑定机器人 | 使用输入框模型，不走知识库 | 不建议允许，直接跳过并提示 |
| 机器人停用 | 提示机器人已停用，可改用输入框模型 | 跳过 |
| 机器人模型配置不存在 | 提示模型配置不可用 | 跳过 |
| 机器人未绑定知识库 | 使用机器人模型，不走知识库 | 使用机器人模型，不走知识库 |
| 绑定知识库已删除 | 忽略失效知识库并记录日志；如果全部失效则跳过检索 | 同左 |
| 图片消息但模型不支持视觉 | 不传图，提示模型不支持图片理解 | 跳过或只处理文本，首版建议跳过图片-only 自动回复 |

## 12. 实现阶段

### 阶段一：后台机器人配置 CRUD

- 落地机器人数据结构。
- “店铺机器人配置”页从占位改成真实列表。
- 支持新建、编辑、删除、启停。
- 模型配置下拉读取现有模型配置。
- 知识库多选读取现有知识库列表。

### 阶段二：平台绑定机器人

- 聚合界面平台按钮右键菜单增加绑定 / 解绑机器人。
- 平台绑定关系持久化。
- 平台按钮可展示当前绑定机器人状态。
- 删除或停用机器人时，绑定关系可识别异常状态。

### 阶段三：生成回复链路接入机器人配置

- 新增统一配置解析方法。
- 手动生成回复优先读取机器人配置。
- 未绑定机器人时回退到输入框模型并跳过知识库。
- 知识库检索范围改为机器人绑定的知识库列表。
- trace 日志记录机器人解析结果。

### 阶段四：自动回复链路接入机器人配置

- 自动回复要求当前平台绑定启用机器人。
- 自动回复复用手动生成回复链路。
- 自动回复日志记录机器人检查结果。
- 机器人停用、模型缺失、未绑定机器人时跳过发送。

### 阶段五：体验增强

- 支持复制机器人。
- 支持按店铺名、模型、状态筛选。
- 支持机器人绑定的知识库失效提醒。
- 支持机器人配置导入导出。
- 支持 Prompt 风格、称呼习惯、是否允许发图等策略字段。

## 13. 与知识库管理的关系

知识库管理负责“知识从哪里来、如何导入、如何检索”。

机器人管理负责“某个平台回复时使用哪些知识库”。

关系如下：

```text
知识库管理
  -> 创建知识库
  -> 导入文档、Excel、图片素材
  -> 建索引

机器人管理
  -> 选择一个或多个知识库
  -> 选择模型
  -> 配置适用店铺和启用状态

聚合平台
  -> 绑定一个机器人
  -> 生成回复时按机器人配置执行
```

因此平台侧不再直接绑定知识库，避免配置入口重复。

## 14. 后续扩展方向

后续可以在机器人上继续扩展策略字段：

- 回复语气：亲切、专业、简洁、热情。
- 常用称呼：亲、宝子、老板等。
- 场景类型：售前、售后、物流、活动、通用。
- 是否允许自动发图。
- 是否允许自动发送多条消息。
- 图片素材库优先级。
- Prompt 模板。
- 自动回复时间段。
- 转人工条件。
- 风险词拦截。

这些扩展都应该挂在机器人配置上，而不是分散到平台按钮或知识库页面里。

## 15. 当前实现记录

截至当前阶段，机器人管理已完成阶段一到阶段五中的主要可用能力，当前主链路已经从“平台直接绑定知识库”切换为“平台绑定机器人，机器人绑定知识库”。

### 15.1 后台机器人配置

已完成：

- AI 客服后台“店铺机器人配置”页已从占位页改为真实机器人列表。
- 机器人配置存储在客户端 `QSettings` 的 `ai/robots/list` 中。
- 支持新建、编辑、删除、启用/停用机器人。
- 支持复制机器人；复制后生成新的 `robot_id`，名称追加“副本”，并默认停用，避免复制后立即影响自动回复。
- 支持按关键词搜索机器人，搜索范围包含机器人名称、ID、模型、知识库、适用店铺和绑定平台。
- 支持按模型筛选、按状态筛选，状态筛选包含启用、停用、已绑定平台。
- 列表会提示机器人绑定到哪些平台。
- 列表会提示模型配置不可用、知识库引用不存在、平台绑定指向已删除机器人等异常状态。
- 删除已绑定平台的机器人时，会提示受影响平台，删除后这些平台会显示机器人失效。

### 15.2 机器人字段

当前机器人 JSON 已包含以下主要字段：

| 字段 | 当前用途 |
| --- | --- |

| `knowledge_base_ids` | 机器人绑定的知识库 ID 列表 |

| `shop_names` | 适用店铺说明，首版仅作展示和筛选 |
| `reply_tone` | 回复语气，会写入大模型系统提示词 |
| `common_address_terms` | 常用称呼，会写入大模型系统提示词 |

### 15.3 聚合平台绑定

已完成：

- 聚合界面左侧具体平台按钮支持右键绑定机器人、查看当前机器人、解绑机器人。
- “全部”按钮作为筛选视图，不参与机器人绑定。
- 平台绑定关系存储在客户端 `QSettings` 的 `ai/platformRobotBindings/<platform>` 中。
- 平台按钮 tooltip 会展示当前绑定机器人状态。
- 如果绑定的机器人被删除，平台按钮和后台机器人页都会提示失效。

### 15.4 生成回复链路

已完成：

- 手动“生成本条回复”和“AI 自动回复”共用机器人运行时配置解析逻辑。
- 平台绑定启用机器人时，使用机器人里的模型配置。
- 平台未绑定机器人时，手动生成回复回退到聚合输入框当前选择模型，并跳过知识库检索。
- 自动回复要求平台绑定启用机器人；未绑定、机器人停用、模型缺失时跳过自动回复并记录日志。
- 知识库检索范围来自机器人绑定的 `knowledge_base_ids`。
- 机器人未绑定知识库时，跳过知识库检索。
- 文本知识库检索和图片素材检索都按机器人绑定的知识库范围执行。
- AI trace 已记录机器人来源、绑定状态、机器人 ID、机器人名称、模型、知识库范围、回复语气、常用称呼、自动发图策略和自动多条消息策略。

### 15.5 回复策略与自动回复

已完成：

- `reply_tone` 和 `common_address_terms` 会拼入最终大模型系统提示词，用于约束回复口吻。
- `allow_auto_send_images` 控制自动回复是否把建议附图加入发送 payload；关闭时只自动发送文字。
- `allow_auto_send_multi_messages` 和 `max_auto_send_messages` 控制自动回复是否允许多条文字消息。
- 自动多条消息不再触发多次独立生成；当前策略是一次客户消息只触发一次 AI 生成。
- 如需多条消息，模型需使用单独一行 `---MSG---` 分隔；发送前会按机器人上限截断。
- 发送前会做相似内容去重，避免“同一个问题连续发送两条近似回复”。
- 客户只回复“可以 / 好 / 嗯 / 行 / 谢谢”等短确认时，会先结合最近聊天语境判断；如果上一条我方回复没有明确等待继续处理，则跳过知识库检索，让模型自然收口。
- 如果上一条我方回复明确在询问是否需要推荐、补充详情、发图或继续处理，短确认场景可以用上一条我方回复构造检索 query，继续推进对应事项。
