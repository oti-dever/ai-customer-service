# 知识库管理实现方案

日期：2026-07-06

## 1. 背景

当前客户端“AI客服后台”的“知识库”页面已经从早期 PoC 目录导入工具升级为通用知识库列表：可以创建不同用途的知识库，导入文档和图片素材，并由机器人选择使用，最终在聚合接待中按平台绑定的机器人生效。

这个形态可以验证本地知识库导入、RAG 检索和图片素材推荐链路，但不适合后续真实多店铺、多平台客服场景：

- 不同店铺或运营入口可能需要使用不同商品知识、售后规则和图片素材。
- 微信、QQ 等平台通常拿不到稳定店铺名，其他电商平台也不一定能稳定获取店铺标识。
- 即使某些平台能拿到店铺名，也可能存在命名不一致、账号切换、页面结构变化等问题。
- 如果把知识库强绑定到“自动识别到的店铺名”，会让知识库生效逻辑依赖不稳定外部信息。

因此，知识库管理应从“目录导入工具”升级为“知识库配置 + 机器人引用”的管理模型。平台侧不再直接绑定知识库，而是绑定机器人；机器人再声明使用哪些知识库。

## 2. 设计原则

### 2.1 知识库不直接依赖店铺识别

后台“知识库”列表中的“绑定店铺”应改为“适用店铺”。

“适用店铺”只作为人工可读的说明或标签，例如：

- 官方旗舰店
- 美女生活馆
- 官方旗舰店、美女生活馆通用
- 微信私域售后通用

它不作为检索路由的硬条件，也不要求客户端必须从平台页面中识别到同名店铺。

### 2.2 真正决定检索范围的是机器人配置

聚合接待界面左侧平台按钮栏中，千牛、拼多多、抖店、微信、QQ 等平台按钮支持右键绑定机器人。平台本身不再直接绑定知识库，知识库检索范围由“当前平台绑定的机器人”决定。

规则如下：

1. 平台已绑定启用机器人时，读取机器人绑定的一个或多个知识库，只检索这些知识库。
2. 平台未绑定机器人时，手动生成回复可回退到输入框模型，但不走知识库检索。
3. 自动回复要求平台绑定启用机器人；未绑定、机器人停用或模型缺失时跳过自动回复。
4. 机器人未绑定知识库时，使用机器人模型生成回复，但跳过知识库检索。
5. 知识库停用或已删除时，即使仍被机器人引用，也不应参与检索，并需要在后台和 trace 中提示失效引用。
6. “适用店铺”只用于列表展示、人工辨识和后续运营维护，不参与自动过滤。

这个方案能兼容拿不到店铺名的平台，也能把“模型、知识库、回复策略、自动回复策略”集中到机器人实体里，避免平台按钮同时维护多类绑定关系。

### 2.3 先做平台级绑定机器人，后续再扩展账号级绑定

第一阶段只做平台级机器人绑定，例如：

- 拼多多 -> 绑定“拼多多键盘售前机器人”
- 微信 -> 绑定“私域售后机器人”
- QQ -> 不绑定机器人，手动生成回复时仅使用输入框模型，不走知识库

后续如果某个平台能稳定拿到账号、店铺、客服工作台实例或店铺 ID，再扩展为：

- 平台级默认机器人
- 平台账号级机器人
- 平台店铺级机器人
- 单会话临时选择机器人或知识库覆盖策略

不要在第一版就把“店铺名识别”作为主路由条件。

## 3. 当前代码基础

### 3.1 后端知识库模型

当前 `python/service/knowledge_store.py` 中已经有 `knowledge_bases` 表，核心字段包括：

- `id`
- `name`
- `description`
- `enabled`
- `platform`
- `shop_id`
- `robot_id`
- `scene`
- `created_at`
- `updated_at`

文档和图片素材分别保存在：

- `knowledge_documents`
- `knowledge_image_assets`

检索时已经过滤启用状态：

```sql
AND b.enabled = 1
```

并且检索方法已支持 `base_ids` 参数。当前 Python 服务的 `/api/knowledge/search` 和 `/api/knowledge/images/search` 已经能接收 `base_ids` 数组。

当前主链路中，`base_ids` 由平台绑定的机器人提供：机器人绑定了哪些知识库，检索时就把这些知识库 ID 作为范围传给 Python 服务。未绑定机器人或机器人未绑定知识库时，客户端会跳过知识库检索，避免误用默认知识库。

### 3.2 客户端知识库页

当前知识库页在 `src/ui/aicustomerservicebackendwindow.cpp` 中构建，主要包含：

- 页面标题“知识库”
- “刷新素材”按钮
- “本地素材目录导入”卡片
- 目录输入框
- “选择目录”
- “导入/重建”
- 文档知识列表
- 图片素材列表

同一文件中已经存在类似图 2 风格的列表 helper：

- `buildProductKbListHeader`
- `buildProductKbDataRow`

当前知识库页已经切换为“知识库列表 + 新建/编辑配置弹窗”的形态。原独立 F&A 占位页不再保留，常见问答通过新建“常见问答知识库”并导入问答文档实现。

### 3.3 聚合接待平台按钮

聚合接待左侧平台工具栏在 `src/ui/aggregatechatform.cpp` 中构建，目前是 `QToolButton + QButtonGroup`：

- 全部
- 千牛
- 拼多多
- 抖店
- 微信
- QQ

当前按钮左键用于筛选会话列表，右键菜单用于绑定/解绑机器人。知识库不再由平台按钮直接绑定，而是由机器人配置页选择。

### 3.4 当前检索硬编码问题

当前聚合接待生成回复时，知识库检索仍硬编码了：

```cpp
QStringLiteral("keyboard-demo-shop")
```

后续接入机器人后，应改为：

- 根据当前会话平台读取该平台绑定的机器人
- 从机器人配置中读取 `knowledge_base_ids`
- 调用知识库检索接口时传入 `base_ids`
- `shop_id` 第一阶段传空，避免旧默认店铺误过滤

## 4. 产品形态

### 4.1 知识库主页面

将顶部“刷新素材”按钮改为：

- `+ 新建知识库`

页面主体改为知识库列表，不再区分“产品知识”和“F&A问答知识库”两个后台入口。

推荐列：

| 列名 | 说明 |
| --- | --- |
| 知识库名称 | 用户填写的知识库名称 |
| 适用店铺 | 人工填写的适用店铺说明，不参与自动路由 |
| 知识库目录 | 本地素材目录 |
| 文档数 | 当前已导入且启用的文档数量 |
| 图片数 | 当前已导入且启用的图片素材数量 |
| 最后更新 | 最近一次保存配置或导入素材时间 |
| 状态 | 启用 / 停用 |
| 操作 | 编辑、启用/停用 |

如果知识库为空，显示空状态：

```text
暂无知识库
点击“新建知识库”添加本地素材目录，并可在聚合接待中为平台绑定使用。
```

现实现应理解为：

```text
暂无知识库
点击“新建知识库”添加本地素材目录；后续可在机器人配置中选择该知识库。
```

### 4.2 知识库配置对话框

点击“新建知识库”或列表中的“编辑”后打开“知识库配置”对话框。

建议字段和控件：

| 字段/区域 | 控件 | 说明 |
| --- | --- | --- |
| 知识库名称 | 输入框 | 必填，例如“官方旗舰店产品知识库” |
| 适用店铺 | 输入框或标签编辑 | 仅展示说明，例如“官方旗舰店、美女生活馆” |
| 知识库目录 | 输入框 + 选择目录按钮 | 本地素材目录 |
| 启用状态 | 开关或复选框 | 新建后默认启用 |
| 导入/重建 | 主按钮 | 将目录中的文档/图片导入当前知识库 |
| 刷新素材 | 次按钮 | 重新读取当前知识库的文档/图片列表 |
| 文档列表 | 表格 | 展示文件名、类型、状态、片段数、更新时间 |
| 图片列表 | 表格 | 展示图片名、类型、分析状态、标签、风险标签、更新时间 |
| 保存 | 主按钮 | 保存名称、适用店铺、目录、启用状态等配置 |
| 关闭 | 次按钮 | 关闭对话框 |

对话框中“导入/重建”应使用当前知识库的 `base_id`，避免同名知识库复用或误写入其他知识库。

## 5. 机器人选择知识库

### 5.1 入口

知识库的使用入口已经迁移到“店铺机器人配置”。聚合接待左侧平台按钮只绑定机器人，不再直接绑定知识库。

后台机器人配置中：

```text
机器人
  -> 选择模型配置
  -> 选择一个或多个知识库
  -> 配置回复语气、常用称呼、是否允许自动发图、是否允许自动发送多条消息
  -> 启用/停用
```

聚合接待平台按钮右键菜单中：

```text
绑定机器人...
查看当前机器人
解绑机器人
```

### 5.2 机器人配置中的知识库选择

机器人配置弹窗中的知识库区域展示已创建知识库的多选列表：

| 选择 | 知识库名称 | 适用店铺 | 状态 |
| --- | --- | --- | --- |

保存机器人后，机器人 JSON 中记录：

```json
{
  "knowledge_base_ids": ["kb_a", "kb_b"],
  "knowledge_base_names": ["键盘产品知识库", "常见问答知识库"]
}
```

如果未勾选任何知识库，可以提示：

```text
该机器人未绑定知识库，生成回复时会使用机器人模型，但跳过知识库检索。
```

### 5.3 检索规则

生成 AI 草稿或自动回复时，根据当前会话平台解析机器人，再计算 `base_ids`：

```text
当前会话 -> platform
  -> 查询平台绑定的 robot_id
  -> 读取机器人配置
  -> 如果机器人启用且 knowledge_base_ids 非空：传 base_ids
  -> 如果机器人未绑定知识库：跳过知识库检索
  -> 如果平台未绑定机器人：跳过知识库检索
```

文档知识检索和图片素材检索都应使用同一套 `base_ids` 规则。

## 6. 数据模型建议

### 6.1 扩展 knowledge_bases

建议为 `knowledge_bases` 增加字段：

```sql
source_directory TEXT NOT NULL DEFAULT ''
applicable_shops TEXT NOT NULL DEFAULT ''
```

说明：

- `source_directory`：保存当前知识库配置的本地素材目录。
- `applicable_shops`：保存人工填写的适用店铺说明。第一版可用纯文本，后续如需结构化再迁移为 JSON。

导入目录完成后，应更新当前知识库的 `updated_at`，使列表“最后更新”与实际操作一致。

### 6.2 历史平台知识库绑定表

早期方案曾建议新增平台直绑知识库表：

```sql
CREATE TABLE IF NOT EXISTS knowledge_platform_bindings (
    id TEXT PRIMARY KEY,
    platform TEXT NOT NULL,
    base_id TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE(platform, base_id)
);
```

当前主链路已改为平台绑定机器人，因此该表不再作为 UI 主入口。若历史数据或旧接口仍存在，可作为兼容层读取或后续迁移参考，不建议继续在新功能中扩展平台直绑知识库。

如果后续仍需要外部服务侧保存平台到机器人的关系，应优先设计 `platform_robot_bindings`，而不是继续扩展 `knowledge_platform_bindings`。

后续扩展账号级、店铺级时，可以增加字段：

```sql
account_id TEXT NOT NULL DEFAULT ''
shop_key TEXT NOT NULL DEFAULT ''
scope TEXT NOT NULL DEFAULT 'platform'
```

但第一版不建议提前引入复杂 scope，避免管理界面和检索逻辑过早复杂化。

当前已有：

- `GET /api/knowledge/bases`
- `POST /api/knowledge/bases`

建议补充：


请求：

```json
{
  "id": "kb_xxx",
  "name": "官方旗舰店产品知识库",
  "applicable_shops": "官方旗舰店、美女生活馆",

  "enabled": true,
  "scene": "reply_draft"

```

可以复用更新接口，也可以单独提供：

```http
POST /api/knowledge/bases/set_enabled
```

请求：

```json
{
  "id": "kb_xxx",
  "enabled": false
}
```

### 7.3 历史平台知识库绑定接口（不再作为主链路）

```http
GET /api/knowledge/platform_bindings?platform=qianniu
```

返回：

```json
{
  "status": "success",
  "platform": "qianniu",
  "base_ids": ["kb_a", "kb_b"]
}
```

### 7.4 历史保存平台知识库绑定接口（不再作为主链路）

```http
POST /api/knowledge/platform_bindings
```

请求：

```json
{
  "platform": "qianniu",
  "base_ids": ["kb_a", "kb_b"]
}
```

如果 `base_ids` 为空数组，表示清除该平台知识库绑定。当前 UI 主链路已经改为“平台绑定机器人”，因此新功能不应继续依赖这些接口决定检索范围；检索范围应来自机器人配置中的 `knowledge_base_ids`。

### 8.2 AI 客服后台

将 `buildProductKnowledgePage()` 从“导入卡片 + 素材列表”改为：

- `+ 新建知识库`
- 知识库列表
- 空状态

新增“知识库配置”对话框：

- 新建时没有 `base_id`，保存后创建 base
- 编辑时加载 base 配置
- 导入/重建时使用当前 `base_id`
- 文档/图片列表按当前 `base_id` 刷新

### 8.3 聚合接待

在 `AggregateChatForm::buildLeftToolBar()` 中为平台按钮设置右键菜单。

建议只对具体平台按钮启用右键绑定：

- 千牛
- 拼多多
- 抖店
- 微信
- QQ

“全部”按钮不建议绑定机器人，因为它是筛选视图，不是实际消息来源平台。

检索前增加机器人绑定解析：

```text
conversationId -> ConversationDao::findById()
  -> conv.platform
  -> loadBoundRobotId(platform)
  -> loadRobotConfig(robot_id)
  -> robot.knowledge_base_ids
  -> searchKnowledge(..., base_ids)
  -> searchKnowledgeImages(..., base_ids)
```

## 9. 兼容策略

### 9.1 旧数据兼容

已有通过 PoC 页面导入的默认知识库可以继续存在。

迁移时：

- 如果 `source_directory` 为空，可以不显示目录，或从首次导入配置后补齐。
- 如果 `applicable_shops` 为空，列表显示“未填写”。
- 已有通过 PoC 页面导入的默认知识库继续保留，但不会在“未绑定机器人”的平台上被隐式检索。
- 平台未绑定机器人时，手动生成回复使用输入框模型，不走知识库检索；自动回复跳过。
- 机器人已绑定知识库时，才按机器人 `knowledge_base_ids` 进入检索范围。

### 9.2 默认知识库

可以保留一个默认知识库，例如：

```text
键盘客服产品知识库 PoC
```

但不应继续在聚合检索中硬编码 `keyboard-demo-shop`。

第一版建议检索时：

- `shop_id` 传空
- `scene` 继续使用 `reply_draft`
- `base_ids` 由平台绑定的机器人决定

## 10. 分阶段落地

### 阶段一：知识库列表和配置弹窗

目标：

- 知识库主页面改为知识库列表
- 支持新建、编辑、启用、停用
- 配置中保存名称、适用店铺、目录
- 导入/重建绑定到具体 `base_id`
- 文档/图片列表在配置弹窗内展示

### 阶段二：机器人引用知识库，平台绑定机器人

目标：

- 机器人配置中支持选择一个或多个知识库。
- 聚合接待左侧平台按钮支持右键绑定机器人。
- 检索时传入机器人绑定的 `knowledge_base_ids`。
- 平台未绑定机器人或机器人未绑定知识库时，跳过知识库检索。

### 阶段三：体验增强

目标：

- 知识库列表展示文档数、图片数、最近导入状态
- 支持查看当前平台绑定的机器人摘要。
- 支持解绑机器人。
- 导入过程显示任务状态、失败原因
- 图片素材支持预览

当前落地：

- `knowledge_bases` 补充最近导入状态、错误、耗时、本次文档数、本次图片数和导入时间。
- 导入/重建开始、成功、部分失败、失败时会更新知识库最近导入状态，后台列表可直接查看。
- 知识库列表新增“最近导入”列，失败原因通过状态提示或单元格悬浮提示查看。
- 图片素材列表新增“预览”操作，可直接查看本地图片并打开原图。
- 聚合接待平台按钮右键“查看当前机器人”会展示已绑定机器人；解绑机器人继续保留。

### 阶段四：更细粒度绑定

目标：

- 平台账号级机器人绑定
- 店铺/工作台实例级机器人绑定
- 单会话临时选择机器人或知识库覆盖策略
- 根据平台侧稳定标识做自动推荐，但仍保留人工绑定优先

## 11. 推荐结论

推荐采用：

```text
知识库配置：名称 + 适用店铺说明 + 本地目录 + 启用状态
机器人使用规则：机器人选择一个或多个知识库
平台使用规则：平台按钮右键绑定一个机器人
默认规则：未绑定机器人或机器人未绑定知识库时跳过知识库检索
检索实现：机器人绑定知识库存在则传 base_ids，不存在则不检索
```

这个方案不依赖各平台是否能拿到店铺名，适合微信、QQ、千牛、拼多多、抖店等混合接入场景，也能复用当前后端已有的 `knowledge_bases.enabled`、`base_ids` 检索过滤和文档/图片素材管理能力。

## 12. 当前实现记录

截至当前阶段，知识库管理先完成阶段一、阶段二和阶段三体验增强，阶段四“更细粒度绑定”暂不实现。

已完成内容：

- AI 客服后台左侧导航已简化为单个“知识库”入口，不再在“知识库”下拆分“产品知识”和“F&A问答知识库”子项。
- 后台“知识库”页面已从 PoC 目录导入工具升级为通用知识库列表。
- 原“F&A问答知识库”占位页已移除；常见问答可通过新建“常见问答知识库”并导入 `问答列表.xlsx` 等文档实现。
- 支持新建、编辑、启用、停用知识库。
- 知识库配置支持名称、适用店铺说明、本地目录、启用状态。
- 导入/重建已绑定到具体 `base_id`，避免同名知识库误复用。
- 文档导入支持 `txt`、`md`、`docx`、`pdf`、`xlsx`、`xlsm`，其中 Excel 会按工作表和表头行转成结构化文本。
- 配置弹窗内支持查看当前知识库的文档列表和图片素材列表。
- 导入/重建支持异步任务，界面显示导入中状态、完成结果和失败原因。
- 知识库列表展示文档数、图片数、最近导入状态、最后更新时间和启用状态。
- 图片素材列表支持预览本地图片，并可打开原图。
- Python 知识库服务曾新增平台知识库绑定表和平台绑定接口；当前主链路已迁移为平台绑定机器人，该接口仅作为历史兼容能力保留。
- 聚合接待左侧平台按钮支持右键绑定机器人、查看当前机器人、解绑机器人。
- 机器人配置中支持选择一个或多个知识库；AI 回复生成前会按当前会话平台解析机器人，再读取机器人绑定的知识库 `base_ids`。
- 平台已绑定启用机器人且机器人绑定知识库时，只检索机器人绑定的知识库。
- 平台未绑定机器人、机器人停用、机器人模型缺失或机器人未绑定知识库时，跳过知识库检索。
- 文本知识库检索和图片素材检索都已支持传入 `base_ids`。
- AI 调用 trace 已记录机器人配置解析状态、绑定机器人、知识库范围、检索耗时、失败阶段和实际使用的 `base_ids`。

暂不实现内容：

- 平台账号级机器人绑定。
- 店铺/工作台实例级机器人绑定。
- 单会话临时选择机器人或知识库覆盖策略。
- 基于平台侧稳定标识的自动推荐机器人。

阶段四保留为后续扩展方向。当前优先继续打磨平台绑定机器人、机器人引用知识库、导入体验、素材推荐准确率和 AI 回复链路稳定性。
